# AI 电商导购后端 AGENTS.md 设计

## 1. 目标

为当前仓库设计一份项目级 `AGENTS.md`，指导编码代理分阶段交付基于 RAG 的 AI 电商导购后端。

后端采用 Go、Hertz 和 Eino Graph。项目覆盖课题要求中的基础能力及全部加分能力，但每一阶段必须形成可运行、可测试、可演示的纵向闭环，当前阶段验收通过后才能进入下一阶段。

客户端不在实现范围内。后端仍需提供稳定、版本化、可供原生客户端消费的 REST 与 SSE 契约。

## 2. 已有项目状态

仓库目前是最小的 Go + Gin + 静态页面模板：

- 服务入口与示例 API 集中在 `main.go`。
- `public/index.html` 是模板展示页。
- 尚无商品领域模型、RAG、Agent、持久化、测试或正式 API 契约。

实施时将移除 Gin 依赖并改用 Hertz，不保留 Gin 兼容层。静态模板是否保留由实际后端需要决定，但不属于核心交付物。

## 3. 方案选择

采用“纵向闭环分阶段”方案，而不是按技术层一次性铺开，或先完成大而全的基础版本再集中追加功能。

选择该方案的原因：

- 每个阶段都能独立演示和验收。
- 能尽早验证 API、Graph 状态和领域边界。
- 降低后期集中返工和功能耦合风险。
- 允许保持小步、可回滚的变更。

## 4. 技术与架构边界

### 4.1 核心技术

- Go 作为唯一后端实现语言。
- Hertz 负责 HTTP 路由、中间件、参数校验、REST、SSE 和服务生命周期。
- Eino Graph 负责 Agent 节点、分支、状态、子图和执行链路编排。
- 关系数据库、向量数据库、缓存、模型、Embedding、VLM、ASR 和 TTS 均通过接口与配置接入，不在 `AGENTS.md` 中绑定单一供应商。
- 生产环境部署到 Vercel。服务入口必须兼容 Vercel 自动注入的 `PORT`，同时保留本地默认端口；不得把 Vercel 系统变量复制成项目密钥。
- Neon 运行时使用池化连接地址，数据库迁移使用直连地址。迁移凭据不属于应用运行时依赖，不应因缺少迁移地址而阻止 Vercel 服务启动。

### 4.2 建议目录职责

- `main.go`：Vercel 零配置 Go 后端与本地开发共用的进程入口和依赖装配。
- `internal/http`：Hertz Handler、路由、中间件、协议转换、错误映射和 SSE。
- `internal/agent`：顶层路由 Graph、共享状态和 Agent 编排。
- `internal/rag`：切片、Embedding、检索、重排与事实校验。
- `internal/catalog`：商品、价格、库存和商品能力等权威事实。
- `internal/conversation`：会话历史、摘要和上下文窗口管理。
- `internal/cart`：购物车领域逻辑。
- `internal/order`：订单确认和模拟下单领域逻辑。
- `internal/multimodal`：VLM、ASR 和 TTS 适配。
- `internal/platform`：数据库、向量库、缓存、外部客户端、日志、指标和追踪。

Handler 只负责协议转换，不直接访问数据库或调用模型。业务层不得依赖 Hertz 类型。Graph Node 不得同时混合提示词、数据库操作和协议输出。

### 4.3 Eino Graph 设计

顶层路由 Graph 组合以下可独立测试的子图：

- `recommendation`：意图理解、查询改写、检索、重排、事实校验和推荐生成。
- `conversation`：多轮上下文、补充条件和会话摘要。
- `commerce`：购物车工具调用、订单确认和模拟下单。
- `multimodal`：图片与音频预处理，并转换为统一语义请求。

每个节点必须具备明确、强类型的输入输出，单一职责，显式依赖，独立超时和错误策略。Graph State 仅保存本次执行所需的结构化上下文；长期会话历史由独立存储负责。禁止使用隐式全局可变状态。

## 5. 分阶段交付

### 阶段一：基础 RAG

实现数据导入、切片与索引，模糊需求理解，商品检索与重排，事实校验，推荐理由，Hertz SSE 流式输出和结构化商品卡片。

链路为：用户请求 → Hertz Handler → Eino Graph → 意图识别 → 商品检索 → 重排 → 商品事实校验 → 推荐生成 → SSE 输出。

验收重点是端到端链路完整、能检索库内商品、推荐依据合理，并且不编造价格、库存、优惠或商品能力。

### 阶段二：对话与 RAG 增强

加入会话存储、上下文摘要、查询改写、属性过滤、混合检索、重排和置信度。支持“再便宜一点”“第二个适合敏感肌吗”等连续追问。

### 阶段三：交易 Agent

实现对话式加购、购物车增删改查、自然语言数量修改、订单信息汇总、确认状态和模拟下单。

购物车、订单和商品查询必须作为受控 Tool 或 Node 接入 Graph。模型不能直接操作数据库。所有写操作需要参数校验、幂等键、事务和审计日志；下单必须先进入显式确认状态。

### 阶段四：多模态

实现图片搜商品、ASR 与 TTS 的后端能力。图片先由 VLM 提取可检索属性，再复用商品 RAG；音频经 ASR 转为文字后进入统一对话链路；回复可按需交给 TTS。

客户端的摄像头、麦克风、录音和播放实现不在范围内。多模态供应商不可用时降级到文字流程。

### 阶段五：工程强化

增加缓存、限流、超时、有限重试、熔断与降级，结构化日志、指标和链路追踪，离线 RAG 评测，并发与流式性能测试，容器化、部署和运维说明。

## 6. API 与事件协议

- 所有正式接口使用 `/api/v1` 前缀。
- 使用统一响应、稳定错误码、请求 ID 和输入校验。
- SSE 至少覆盖 `message.delta`、`product.card`、`tool.status`、`error` 和 `done` 事件。
- SSE 发生异常时仍需发出明确的错误与终止信号。
- 交易写接口支持幂等键。
- API 变更需考虑向后兼容，并同步更新契约文档。

## 7. 事实、安全与隐私规则

- 商品价格、库存、优惠和能力只能来自权威结构化数据源。
- 向量检索结果只是候选，必须经过事实校验后才能输出。
- 检索为空或事实不完整时，明确说明无法确认，禁止模型补全猜测。
- 密钥只从环境变量或密钥管理服务读取，不得写入代码、Prompt、测试夹具、日志、文档或版本库。
- 配置加载优先使用显式项目变量，并把 Vercel 自动提供的 `VERCEL_ENV` 作为运行环境回退值；`PORT` 和 `VERCEL_*` 变量由平台管理，不在 `.env.example` 中伪造。
- Vercel 的 Production、Preview 和 Development 环境必须分别配置数据库和模型凭据；Preview 不得默认连接生产数据库分支。
- 运行时只要求当前阶段实际使用的变量。后续阶段的模型、多模态或观测变量在对应功能启用时再校验，避免骨架阶段因无关变量缺失而无法启动。
- 原课题文档中出现的凭据不得复制到仓库，并应由凭据所有者轮换。
- 日志必须脱敏，不记录完整用户输入、认证信息或供应商秘密响应。
- 只使用脱敏商品和测试数据。

## 8. 错误处理与降级

- API 不向客户端暴露内部堆栈、Prompt 或原始供应商错误。
- Graph Node 分别配置超时和错误策略。
- 仅对可安全重试的模型、Embedding 和只读检索执行有上限的重试。
- 交易写操作不得自动进行可能产生重复副作用的重试。
- 多模态失败时降级到文字交互；模型生成失败时返回稳定错误并结束流。
- 价格、库存或优惠校验失败时不得输出未确认值。

## 9. 测试与阶段门禁

每个阶段必须在进入下一阶段前完成对应实现、测试、文档和验收记录。

测试范围包括：

- 领域服务、Graph Node 和状态转换的单元测试。
- 数据库、向量检索和外部适配层的集成测试。
- Hertz API、错误码、输入校验和 SSE 事件顺序测试。
- 固定评测集上的召回、推荐依据、事实一致性和拒绝编造评测。
- 交易流程的重复请求、并发修改、非法状态转换、事务和回滚测试。
- 最终阶段的并发、首个 SSE 事件延迟、完整响应耗时和资源占用基线。

执行代理不得通过删除测试、跳过测试或降低断言强度来获得通过。声称完成前必须实际运行格式化、静态检查、单元测试、相关集成测试和阶段验收命令。

## 10. AGENTS.md 执行规则

最终 `AGENTS.md` 将要求编码代理：

1. 先检查仓库、现有改动、当前阶段与相关文档。
2. 在修改前给出与任务复杂度相称的计划。
3. 遵守阶段门禁，不提前堆叠后续阶段功能。
4. 优先测试驱动，实施最小、聚焦且可回滚的变更。
5. 遵守目录职责、依赖方向和接口隔离。
6. 保护用户已有改动，不执行破坏性 Git 操作，不做无关重构。
7. 更新 README、环境变量示例、API 契约、数据导入、Graph、阶段验收和部署文档。
8. 在完成声明中提供实际验证证据和仍存在的限制。

## 11. 非目标

- 不实现 iOS 或 Android 客户端。
- 不接入真实支付或真实订单履约。
- 不允许模型绕过领域服务直接修改持久化数据。
- 不在项目级指令中硬编码单一云厂商或数据库供应商。
- 不在当前任务中实现上述后端功能；当前任务只设计并生成指导后续开发的 `AGENTS.md`。

## 12. 完成标准

本设计任务在以下条件满足时完成：

- 仓库根目录存在一份无占位符、可直接指导编码代理工作的 `AGENTS.md`。
- 文件明确采用 Hertz 与 Eino Graph。
- 文件明确后端范围、五阶段交付顺序、架构边界、安全规则、API 契约、测试门禁和文档要求。
- 文件不包含任何真实密钥或敏感凭据。
- 文件内容与当前仓库状态及本设计保持一致。
